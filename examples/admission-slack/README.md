# Admission slack — the experiment

The second result beside the main guarantee: **which superfluous calls does the
monitor admit along with the necessary one, and what additional ground tells them
apart?** The statement, the scope and what is *not* claimed live in
[`docs/admission-slack.md`](../../docs/admission-slack.md); every number lives in
[`results.md`](results.md), which is generated from the records and not edited by
hand.

Nothing here needs an API key, a model or the network: the plans are AgentDojo's
own reference plans (`ground_truth`) and every verdict is the real kernel's.

```
pip install agentdojo          # the only extra dependency
```

## The pieces

| file | what it is |
|---|---|
| `observation.py` | the monitor's observation language `π`, transcribed from the arguments the gates are called with in `ToolCallGovernor.evaluate` — plus the verdict helper the experiment decides with |
| `harvest.py` | where alternatives come from: environment values grouped by syntactic shape and structural slot, prompt tokens, allowlist members; and the exclusion of values the rest of the plan needs |
| `pairs.py` | the deciding experiment: replay a plan prefix, judge the needed call, judge every substitution from the same state, dispatch each on a fork of the environment |
| `cases.py` | the hand-checked authorization analysis (step 3), as data: instruction, trusted basis, why the needed call is authorized, why the substitution is not, and the effect it has |
| `enrichment.py` | step 4: install each candidate additional ground on the real governor, re-judge both calls, and price the ground over the whole suite |
| `neighbor/*.rego`, `neighbor_opa.py` | step 5: the same pairs through Open Policy Agent, with and without axor's observations |
| `report.py` | turns the records into `results.md` |
| `records/` | the small records of the runs of record (enrichment + neighbour verdicts). The per-pair dumps are large and are regenerated by the commands below. |

## Reproducing the runs of record

```bash
# step 2 — the pairs, as deployed in §6 and under a widened declaration
python examples/admission-slack/pairs.py --all --max-per-arg 16 --out runs/
python examples/admission-slack/pairs.py --suite banking --config banking_tuned.yaml \
    --max-per-arg 16 --out runs/
python examples/admission-slack/pairs.py --all --max-per-arg 16 --declare-effectful --out runs/
python examples/admission-slack/pairs.py --suite banking --config banking_tuned.yaml \
    --max-per-arg 16 --declare-effectful --out runs/

# step 4 — which additional ground separates a confirmed pair, and its price
python examples/admission-slack/enrichment.py --json runs/enrichment.json

# step 5 — the same pairs through OPA (needs the opa binary)
for g in as_deployed widen_key bind_and_key; do
  python examples/admission-slack/neighbor_opa.py --opa ./opa --ground "$g" --out runs/neighbor/
done

# the tables of record
python examples/admission-slack/report.py runs/ \
    --enrichment runs/enrichment.json --neighbor runs/neighbor/ > examples/admission-slack/results.md
```

A single case, when you only want to look at one pair:

```bash
python examples/admission-slack/pairs.py --suite banking --task user_task_9
python examples/admission-slack/enrichment.py --case B-named-standing-order
```

## The one obligation the experiment checks on itself

`π` is read off this implementation, so the experiment verifies on **every** pair
that equal projections got equal verdicts, and reports any counterexample as
`pi_violations` rather than hiding it. A violation would mean the observation
language in `observation.py` is missing something a gate reads. Over the runs of
record: 3100 pairs, 0 violations.
