# Negative-control matrix

One condition at a time: remove it, count the effects that leave the constraint
it exists for; restore it, count again; and check that the legitimate call still
executes with it in place. Effects are read from the handlers' own state (a bank
ledger, a payee store, a public bucket) behind the real `IntentLoop` — not from
verdicts.

The table is generated by `tests/negative_controls.py` (`render_markdown()`), and
`tests/integration/test_negative_control_matrix.py` fails if this file differs
from a fresh run. Each scenario runs one attack proposal and one legitimate call
per arm, in a fresh session; "restored" is a third fresh run with the condition
back in place. The counts are therefore per proposal, not rates: they show that
each condition is load-bearing for its constraint in isolation, not how often an
agent would attempt the attack.

**What `0 → 1 → 0` shows, and what it does not.** It shows that, *in this
construction*, nothing else stands in for the condition: remove it and the
constraint is violated. It does not show that the particular mechanism is
necessary in general. Confidentiality, for instance, can be had by a design with
no session floor (e.g. information-flow labels carried on values to the sink); the
row says only that, in Axor as built, the floor is the component that carries it.

Reading the rows:

- **Contract rows** isolate T4: the value policies are identical in both arms;
  only the consumption contract is removed. The effect that appears is the
  handler's own default, alias or formatting — the predicate's verdict was
  correct throughout.
- **Floor** and **approval** rows isolate a permitting ground: the floor arms only
  on a *declared* sensitive read, and the approval relaxes the consequence axis
  for whatever its issuer says yes to. The approval row is the producer negative
  control — a {yes, no} codomain and a steerable producer.
- **Integrity** and **allowlist** rows show two independent grounds for "the
  destination is not attacker-chosen": the allowlist row runs with integrity set
  to `clean` so the enum is the only barrier, and the integrity row runs with no
  allowlist so the context root is.
- **Path row** is not an effect control. The contract refuses the configuration
  (an `enum` on a resolved path); it does not by itself keep the bytes in the
  root — that is the path obligation, which is a fuzz-tested one.
